# Security policy

Do not open a public issue for exposed credentials, restricted records or a
path that permits unintended data disclosure. Use GitHub's private
vulnerability-reporting button on this repository if enabled; otherwise
contact the repository owner through a private channel before sharing details.
Do not include a secret or restricted record in a public issue or pull request.

The release boundary rejects common credential filenames, private-key files,
model checkpoints and restricted/raw data paths. This check supplements, but
does not replace, GitHub secret scanning and manual licence review.

Security fixes are assessed for the maintained default branch. Tagged release
support will be described when the first release tag is issued.
